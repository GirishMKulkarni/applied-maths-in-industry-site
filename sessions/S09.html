The problem

A bank is about to approve a loan. Before it releases the money it wants one answer: will this borrower repay, or default? A payments company watching a UPI transaction wants the same kind of answer in a fraction of a second: is this genuine, or fraud? A telecom looking at a customer's last few months wants to know: will they leave for another network next month, or stay?

Every one of these is a yes-or-no question answered from data. Last time you predicted a number, like a flat's price. Today you predict a category. This is the other half of everyday machine learning, and it powers a huge share of what banks, payment apps and shops actually run in production.

The one idea

Picture the past cases as coloured dots. Borrowers who repaid in blue, those who defaulted in red, spread out by whatever we measured about them. A classifier draws a boundary that separates the two colours as cleanly as it can. For a new case we see which side of the boundary it falls on, and that is our answer.

There are three classic ways to draw that boundary, and today you build all three on the same data:

  1. Logistic regression — the linear model you already know, plus a sigmoid curve that turns its score into a probability between 0 and 1. Straight boundary, fast, and it tells you how sure it is.
  2. KNN (k-nearest neighbours) — a lazy learner. It stores the training cases and classifies a new case by a majority vote of the k stored cases nearest to it. No training at all; the boundary is whatever the data says.
  3. SVM (support vector machine) — it places the boundary to leave the widest empty "street" between the classes, using only the borderline cases (the support vectors) that sit on the street's edge. With the RBF kernel that boundary can bend into a smooth curve.

Same job, three different approaches, and the honest message of the day: no single classifier is best. The shape of the data decides — a straight line is plenty when the groups are neatly separated, and curved boundaries win when they are not. Which brings the real lesson: how do you judge any of them honestly?

There is a catch, and it is the second half of today. When "yes" is rare, and in fraud or disease it always is, plain accuracy becomes a liar. A model that lazily says "no" to everything can be right 95% of the time and still catch zero fraud. So you will judge a classifier the way industry does: the confusion matrix, precision, recall, F1 and ROC-AUC — and you will move the threshold to trade catching more cases against raising fewer false alarms.

For the mathematically curious (optional)

Everything above is enough to do the lab. This box is the extra depth for those who want it, and none of it is needed to finish.

Logistic regression first computes the same linear score you met in regression, z = wᵀx + b, then passes it through the sigmoid σ(z) = 1 / (1 + e^(−z)), which squashes any real number into the interval (0, 1). That output is read as a conditional probability, P(class = 1 | x): the chance the label is 1 given what we observed. The decision boundary is the set of points where z = 0, so σ(z) = 0.5; because z is linear in x, that frontier is a straight line (a flat plane in higher dimensions). Training does not use squared error. It uses cross-entropy, also called log-loss: for each case take the probability the model gave the correct answer and score it as −log(that probability), then average. A confident correct answer costs almost nothing; a confident wrong answer costs a lot. This comes straight from maximum likelihood: minimising cross-entropy is the same as maximising the probability of the labels we actually observed. The Stretch cell in the first notebook shows the sigmoid and the log-loss computed by hand, matching what scikit-learn does for you.

KNN is defined by a distance and a vote. The default distance is the Euclidean distance, d(x, x′) = √(Σ(xᵢ − xᵢ′)²), the straight-line distance you know from the Pythagorean theorem. For a new point, take the k stored points with the smallest distance and let them vote; the majority class wins. Because distance adds up contributions from every feature, a feature with a large range silently dominates — which is why KNN (like SVM) demands feature scaling, usually a StandardScaler that gives every feature mean 0 and variance 1. Training is effectively nil; the cost is paid at prediction time, when the new point must be compared with every stored point.

SVM chooses the boundary with the largest margin — the widest empty strip between the classes. If the hyperplane is w·x + b = 0, the margin width is 2 / ‖w‖, so training minimises ½‖w‖² subject to every point being on the correct side (allowing soft margins controlled by the cost C). Only the support vectors — the points exactly on the margin edge — constrain the solution, so moving any other point leaves the boundary unchanged. The kernel trick makes the boundary bend: the RBF kernel K(x, x′) = exp(−γ‖x − x′‖²) corresponds to mapping the points into a higher dimension where they are linearly separable, without ever computing that map explicitly. C and γ are the two knobs you tune.

New words in this session

  • classifier — a model that sorts each case into one of a few categories.
  • logistic regression — the classic classifier: a linear score squashed into a probability.
  • sigmoid — the S-shaped curve that turns any number into a value between 0 and 1.
  • decision boundary — the frontier where the model switches its vote from one class to the other.
  • KNN (k-nearest neighbours) — a classifier that labels a new case by a majority vote of the k stored cases closest to it; it does no real training.
  • Euclidean distance — the straight-line distance between two points.
  • SVM (support vector machine) — a classifier that places the boundary to leave the widest gap (margin) between the two classes.
  • support vector — one of the borderline cases sitting on the edge of that gap; only these points decide where the SVM boundary goes.
  • kernel — a trick that lets an SVM bend its boundary into a curve (e.g. the RBF kernel) instead of a straight line.
  • feature scaling — putting every feature on a comparable scale (e.g. with a StandardScaler) so no single large-range column dominates a distance; KNN and SVM need it.
  • confusion matrix — the table of the four counts: right and wrong, for each class.
  • precision / recall — of the cases we flagged, how many were real; and of the real ones, how many we caught.
  • ROC-AUC — one number for how well the model ranks real positives above the rest; 1.0 is perfect, 0.5 is guessing.
  • threshold — the cut-off probability at which we decide to call a case "yes".

Full definitions are in the glossary.

1 · The Problem

  • We predict numbers. Now predict categories.

Last Time: Linear Regression

  • Predict a NUMBER from inputs (house price, temperature, demand).
  • Model draws a line THROUGH the data points.
  • Output can be any number (−∞ to +∞).

Linear Regression Review

A line through the data points. Input feature → predicted number.

Today: Predict a Category

  • Now predict a CATEGORY (yes/no).
  • Will this loan default? → Yes or No
  • Is this email spam? → Spam or Not
  • Is this transaction fraud? → Fraud or Genuine
  • Which digit is this? (0–9) → 10 categories

Classification: Separate Two Groups

  • Each dot = one past case with known category.
  • New case arrives → which side does it fall on?
  • That side is the prediction.

Draw a line BETWEEN the groups, not THROUGH them.

Why Not Just Linear Regression?

  • Regression outputs any number. We need a YES/NO and a probability.
  • Could threshold the output, but where? It's arbitrary.
  • We also want HOW SURE we are (a probability between 0 and 1).
  • Each classifier today solves this differently.

2 · Logistic Regression

  • Linear regression + sigmoid → probability

The Core Idea

  • Start with a linear regression (you already know this).
  • Compute a score = w₁x₁ + w₂x₂ + ... + b
  • Pass the score through a SIGMOID function.
  • The sigmoid squashes any number into a probability between 0 and 1.
  • Probability ≥ 0.5 → predict YES. Probability < 0.5 → predict NO.
  • Logistic Regression = Linear Regression + Sigmoid.

The Sigmoid Function

  • Very negative score → P ≈ 0 (sure Class A).
  • Very positive score → P ≈ 1 (sure Class B).
  • Score = 0 → P = 0.5 (unsure — on the fence).
  • This converts regression output into a meaningful probability.

Any number goes in. A probability between 0 and 1 comes out.

Logistic Regression Pipeline

  • You already know the weighted sum from linear regression.
  • The sigmoid is the new part — makes the output a probability.
  • You get a yes/no AND a 'how sure' number.

Clues → weighted sum → sigmoid → probability → class.

How Does It Learn?

  • Adjusts weights to minimize cross-entropy loss.
  • Cross-entropy: heavily penalizes confident WRONG predictions.
  • True answer = YES, model says P = 0.05 → huge penalty.
  • True answer = YES, model says P = 0.95 → tiny penalty.
  • This forces the model to be accurate AND honest about uncertainty.
  • L = −(1/N) Σᵢ [ yᵢ·ln pᵢ + (1−yᵢ)·ln(1−pᵢ) ]

Cross-entropy (log) loss — confident mistakes cost a lot

Cross-Entropy Loss

  • Cross-entropy is the standard loss for classification.
  • Squared error (from regression) is too weak for classification.

Confidently wrong = huge penalty. Correct & confident = tiny penalty.

When to Use Logistic Regression

  • You need interpretable probabilities, not just yes/no.
  • The boundary is roughly straight (linear classifier).
  • You have many features (even thousands).
  • You want a fast baseline to compare against.
  • WARNING: only draws straight boundaries.

3 · Judging Any Classifier

  • How do we trust any of these models? Judge, don't guess.

Why Accuracy Can Lie

  • Accuracy = correct / total predictions.
  • If 99% of cases are 'NO', saying 'NO' always = 99% accuracy.
  • ...but catches ZERO of the 'YES' cases you care about.
  • Accuracy is misleading when classes are imbalanced.

Confusion Matrix

  • True Positive (TP) — caught a real YES.
  • False Positive (FP) — false alarm (wrong YES).
  • False Negative (FN) — missed a real YES (dangerous).
  • True Negative (TN) — correctly cleared a NO.
  • All evaluation metrics come from these 4 numbers.

Every prediction falls into one of four boxes.

Precision and Recall

  • Precision: Of the ones we flagged as YES, how many were right?
  • Precision = TP / (TP + FP) — high = few false alarms.
  • Use when false alarms are expensive (spam filter, fraud alerts).
  • Recall: Of the real YES cases, how many did we catch?
  • Recall = TP / (TP + FN) — high = caught most positives.
  • Use when missing a YES is dangerous (cancer screening, fraud).
  • F1 Score = harmonic mean of precision and recall.

4 · K-Nearest Neighbours

  • A completely different approach: no training, just ask neighbours

What is KNN?

  • Instance-based, lazy learner — NO training phase.
  • It simply stores the entire training dataset in memory.
  • No computations or optimization during training.
  • All the work happens during prediction (inference).
  • When a new point arrives: find k closest neighbours, take a vote.

KNN: How It Works

  • Step 1: Compute distance to every stored point.
  • Step 2: Find the k closest points (nearest neighbours).
  • Step 3: Majority vote among them → predicted class.
  • Distance = Euclidean (straight-line) by default.

k = 5. Three neighbours say Class A, two say Class B → predict Class A.

KNN: Inference Phase in Detail

  • Step 1 — Calculate Distances:
  • Compute distance between new point and EVERY training point.
  • Euclidean: √((x₁−x₁')² + (x₂−x₂')² + ...) [default]
  • Manhattan: |x₁−x₁'| + |x₂−x₂'| + ...
  • Step 2 — Find Nearest Neighbours:
  • Pick the k points with smallest distances.
  • Step 3 — Make a Prediction:
  • Classification → majority vote among the k neighbours.
  • k=5, 3 say A, 2 say B → predict A.

Key Hyperparameters

  • k (Number of Neighbours):
  • Small k (e.g. 1) → follows noise (overfitting, high variance).
  • Large k → too smooth (underfitting, high bias).
  • Typically chosen by cross-validation (try 3, 5, 7, 15...).
  • Use odd k to avoid ties.
  • Distance Metric:
  • Euclidean — default for continuous data.
  • Manhattan — useful when features are on different scales.
  • Cosine — ideal for text data (magnitude doesn't matter).

Why Scaling is Critical

  • Distance calculation gives equal weight to every feature.
  • Income (₹0–50L) will dominate Age (0–100) unless scaled.
  • SOLUTION: StandardScaler() before KNN.
  • SVM has the same requirement — always scale for both.

Strengths and Weaknesses

  • Strengths:
  • Simple and intuitive.
  • No assumptions about data distribution.
  • Works well for small/medium datasets with few features.
  • Weaknesses:
  • Slow prediction — scans ALL data every time.
  • Sensitive to irrelevant features.
  • Curse of dimensionality — performance degrades with many features.
  • Needs careful tuning of k and distance metric.

5 · Support Vector Machine

  • Find the widest possible street between the classes

The Core Idea

  • SVMs find the optimal hyperplane that separates the classes.
  • The hyperplane maximizes the MARGIN — the distance to the nearest points.
  • Data points closest to the hyperplane = SUPPORT VECTORS.
  • Only the support vectors matter — move other points and the boundary stays.
  • Wider margin = more room for error = better generalization.

SVM: The Widest Street

  • Maximize the margin (street width) between classes.
  • Only support vectors define the boundary — rest don't matter.
  • This makes SVM robust and it generalizes well.

Solid line = decision boundary. Dashed lines = margin edges. Green circles = support vectors.

How SVMs Work: Mathematical Idea

  • Hyperplane equation: w·x + b = 0
  • w = weight vector (normal to hyperplane), b = bias.
  • Margin = 2 / ||w|| — the distance between the two class boundaries.
  • Goal: minimize ½||w||² subject to correct classification of all points.
  • Points with margin violations become support vectors.

The Kernel Trick

  • Real data is often NOT separable by a straight line.
  • Kernels map data into higher dimensions where it becomes separable.
  • You don't compute the mapping — the kernel does it implicitly.
  • Linear kernel: straight boundary (same as logistic regression).
  • RBF (Radial Basis Function) kernel: smooth curve.
  • Polynomial kernel: polynomial curve.
  • You just pick the kernel — SVM handles the math.

Training and Inference

  • Training:
  • 1. Input training data X and labels y.
  • 2. Choose a kernel (linear, RBF, polynomial).
  • 3. Solve optimization to find w and b (maximize margin).
  • 4. Identify support vectors — points on the margin edge.
  • Inference (Prediction):
  • 1. Compute f(x_new) = w·x_new + b (or kernel version).
  • 2. If f(x_new) ≥ 0 → Class +1. If f(x_new) < 0 → Class −1.

Key Parameters (Hyperparameters)

  • C (Regularization): trade-off between margin width and errors.
  • Small C → wider margin, allows some misclassifications (better generalization).
  • Large C → narrower margin, classifies perfectly (risk of overfitting).
  • Gamma (γ) — only for RBF kernel:
  • Low gamma → far points influence boundary (smooth).
  • High gamma → only close points influence boundary (wobbly).
  • ALWAYS scale features before SVM.

Advantages and Disadvantages

  • Advantages:
  • Effective in high-dimensional spaces (e.g. text classification).
  • Works well with small datasets.
  • Versatile — different kernels for different data shapes.
  • Disadvantages:
  • Computationally expensive for large datasets (O(n²) or O(n³)).
  • Requires careful tuning of C, kernel, and gamma.
  • Harder to interpret (especially with non-linear kernels).

6 · Comparing the Three

  • Same job, different approaches

Three Boundaries on Same Data

  • Logistic: straight line — simple, interpretable, gives probabilities.
  • KNN: wobbly local boundary — no training, needs scaling.
  • SVM-RBF: smooth curve — powerful, needs tuning.
  • No single classifier is 'best' — data shape determines the choice.

Same 300 points. Left: Logistic (straight). Middle: KNN (local). Right: SVM-RBF (smooth).

Which Classifier When?

How to Choose in Practice

  • Start with Logistic Regression (baseline).
  • If data is non-linear and small → try SVM with RBF kernel.
  • If data has few features and irregular boundary → try KNN.
  • Let evaluation metrics guide the final choice.
  • Scale features for KNN and SVM (not needed for logistic regression).

Key Takeaways

  • Classification = predict a category, not a number.
  • Logistic Regression: linear regression + sigmoid (gives probabilities).
  • KNN: no training — store data, vote by k nearest neighbours.
  • SVM: find the widest street between classes (margin maximization).
  • No single classifier is best — let evaluation metrics decide.
  • Precision, Recall, and F1 tell the honest story, not accuracy alone.
