S02 · Doing Maths on Whole Lists of Numbers (NumPy)

New here? Start with these

Short, picture-first notes for anything below that is unfamiliar. Ten minutes each is plenty. You do not need a maths or a coding background to follow this session.

  • Vectors and matrices
  • Python in 15 minutes
  • Glossary

The problem

A property website like MagicBricks holds a huge table of past flats. One row per flat, and columns for the numbers it knows: size in square feet, age, distance to the nearest metro, price. There are thousands of rows. Now the business wants to raise every listed price by 8 percent for the new financial year, and separately work out a fair price for a flat nobody has listed yet.

You could open the table and change prices one cell at a time. Nobody does that. Today you learn the tool that does arithmetic on a whole column, or a whole table, in a single line, and does it fast enough for millions of rows.

The one idea

A plain Python list can hold a few numbers, but to do maths across it you have to write a loop that crawls through one number at a time. numpy gives you a better container called an array. An array is still just a list of numbers (or a table of numbers, if you stack several lists), but you can do maths on all of it at once.

Picture it like a spreadsheet column. Multiply the whole column by 1.08 and every price rises together. Add two columns and they add up row by row. No loop, less code, and it runs at the speed of the language the computer really thinks in.

That is the whole session. A list of numbers, a table of numbers, and doing maths on all of them in one stroke.

What you'll build today

  1. Make lists and tables of numbers, and read off how big they are.
  2. Do arithmetic on a whole list at once: raise every price, add two lists, scale.
  3. Pull out one row, one column, or a small block from a table.
  4. Solve a small "find the unknowns" problem (two prices from two clues) in one line.
  5. Fit a straight line through noisy data and use it to predict a new value.

You don't need to already know

We build all of this from scratch today, in plain steps:

  • how to do maths on a whole list at once instead of writing a loop,
  • how to ask the computer to find unknown values that fit some facts,

For the mathematically curious (optional)

Everything above is enough to do the whole lab. This box is the extra depth for those who want it, and none of it is needed to finish.

Today's array is exactly the linear algebra you may have met on paper. A 1-D array is a vector in ℝⁿ; a 2-D array is a matrix, a linear map from ℝⁿ to ℝᵐ; a higher array is a tensor. Element-wise * is the Hadamard product, while @ is true matrix multiplication, so wᵀx becomes w @ x and a matrix acts on a vector as A @ x.

np.linalg.solve(A, b) solves Ax = b by an LU factorisation, which is faster and more stable than forming A⁻¹. np.linalg.eig returns the eigenvalues and eigenvectors — the directions a matrix only stretches, Av = λv, the engine behind PCA in Session 11. np.linalg.svd gives the singular value decomposition A = UΣVᵀ, which exists for every matrix and turns "multiply by A" into rotate, stretch, rotate; keeping the largest singular values is how image and data compression work. The line-fitting lab is least squares: ŷ = Xw is the projection of y onto the column space of X, and the orthogonality of the residual gives the normal equation XᵀX w = Xᵀy, which the Stretch cell solves by hand and checks against np.linalg.lstsq. All of this is a bonus, never a gate.

New words in this session

  • array — a list (or table) of numbers you can do fast maths on all at once.
  • shape — how big an array is along each direction, like (3, 4) for 3 rows and 4 columns.
  • vector / matrix — a list of numbers, and a table of numbers (rows and columns).
  • broadcasting — NumPy stretching a smaller array to fit a bigger one so they combine without a loop.
  • solve a system — give the computer some facts and ask it to find the unknown values that fit.
  • least squares — pick the straight line whose total miss from the data is smallest.
