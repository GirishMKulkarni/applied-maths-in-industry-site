S08 · A Steadier House-Price Model — Regularization and Your First Full Project

The problem

In Session 7 you built a house-price model for a property website: type in a flat's details, get an estimated price. It worked well on the flats it had learned from. But a real site sees flats it has never seen before, in localities that barely showed up in the training data. When a model leans too hard on one odd detail of the flats it trained on, it can quote a wild price the moment it meets something new. A ₹80 lakh flat gets tagged at ₹2 crore because of one feature the model over-trusted. That is the failure we fix today, and then we package the whole thing into a project you could actually hand to someone.

The one idea

Left alone, a model will grab any pattern that helps it fit the flats it has already seen, even a coincidence. Regularization is a gentle rule that says: "don't over-trust any one feature." We turn down the volume on the model's weights, so no single feature is allowed to shout. The model fits the training flats slightly less snugly, and in exchange it does better on the flats it has never seen. That trade is almost always worth it.

There is one knob, usually called alpha, that sets how firmly we turn the volume down. Small alpha, barely any effect. Large alpha, everything is quietened. Most of today is learning to set that knob honestly instead of guessing.

What you'll build today

  1. Make a small dataset where some columns are pure noise, and watch a plain model over-trust them.
  2. Add a penalty and see two styles of "turn it down": Ridge quietly shrinks every weight, Lasso switches the useless ones off completely.
  3. Load real California housing data and lock away a test set before you touch anything.
  4. Bundle the data-prep and the model into one tidy object (a Pipeline) that does all the preparation and the model together, so nothing leaks.
  5. Let cross-validation choose the alpha knob for you, then score the model once, honestly, on the flats it never saw.
  6. Read the model back in plain language and write up what actually drives the price. The result is your first full project deliverable: a tuned house-price predictor.

You don't need to already know

We teach all of today's new pieces from scratch, in plain steps:

  • what it means to "scale" features so they are on a comparable footing,
  • what a Pipeline is (one object that does the prep and the model together),
  • what cross-validation does and why it beats guessing the knob by hand.

By the end you can

  • Explain Ridge as "shrink every weight a little" and Lasso as "switch some weights off entirely (feature selection)".
  • Set the penalty knob alpha with cross-validation instead of guessing.
  • Build a scikit-learn Pipeline that scales inside the model, so no information leaks from the test set into training.
  • Score a model honestly on a held-out test set and read MSE, MAE and R².
  • Turn the fitted model into a plain-language explanation of what drives the price.

For the mathematically curious (optional)

Everything above is enough to do the lab. This box is the extra depth for those who want it, and none of it is needed to finish.

The "penalty" has an exact form. Measure the size of the weight vector w with a norm and add it to the least-squares loss. Using the squared L2 norm, ‖w‖₂² = w₁² + w₂² + …, gives Ridge; using the L1 norm, ‖w‖₁ = |w₁| + |w₂| + …, gives Lasso:

Ridge:  minimise   Σ (yᵢ − ŷᵢ)²  +  alpha · ‖w‖₂²
Lasso:  minimise   Σ (yᵢ − ŷᵢ)²  +  alpha · ‖w‖₁

Both keep the whole problem convex — a single bowl with one lowest point — so there is still exactly one best answer and it is reliable to find. The reason Lasso zeroes coefficients out while Ridge does not is geometric: the L1 "diamond" has sharp corners on the axes, and the best solution tends to land on a corner, where some weights are exactly zero. Turning alpha up and down is the bias-variance trade-off made into one tunable dial: small alpha means low bias and high variance (overfitting), large alpha means the opposite (underfitting), and cross-validation finds the sweet spot between them. All of this is a bonus, not a gate.

New words in this session

  • regularization — a gentle rule that discourages a model from over-trusting any one feature, so it does better on new data.
  • penalty / alpha — the size charge added to the loss; alpha sets how strong it is.
  • Ridge — regularization that shrinks every weight toward zero, but never to exactly zero.
  • Lasso — regularization that pushes some weights to exactly zero, dropping those features for you.
  • ElasticNet — a blend of Ridge and Lasso.
  • standardise (scaling) — rescale each feature to a comparable footing so the penalty treats them fairly.
  • Pipeline — one object that does the data-prep and the model together, so the same steps run the same way every time.
  • cross-validation — try a setting on several train/check splits and average, to choose a knob without touching the test set.

Full definitions are in the glossary.
