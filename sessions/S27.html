The problem

Over the last weeks you have trained real models: a flat-price estimator, a loan-risk classifier, a demand forecast. Each one works beautifully, but only in one place: a notebook, on your laptop, where only you can run it. Your family cannot try it. A recruiter cannot click it. A client cannot use it. A model that nobody else can reach might as well not exist.

Today you fix that. You take one trained model and put it online as a tiny web app, so anyone with the link can open it on their phone and use it. Free, no credit card, no servers to rent. By the end you have a working link you can text to whoever you like.

The one idea

A trained model is just a function: numbers go in, an answer comes out. Give it a flat's size and locality, it hands back a price. Give it a flower's four measurements, it hands back a species. That is all a model is once it is trained.

Deploying it means giving that function a public address on the internet. Picture your model as a vending machine. Right now it sits in your bedroom, so only you can buy from it. Deployment wheels the same machine into a busy market: same buttons, same output, but now anyone walking past can use it. Nothing about the model changes. Only its reach does.

Everything today is plumbing around that one function: collect the inputs a user types, call the function, show the answer back.

What you'll build today

  1. Train a tiny classifier and check it honestly on data it has never seen.
  2. Save the trained model to a file with joblib, then load it back and predict, with no retraining.
  3. Write the web app (app.py) straight from the notebook and read it block by block.
  4. Follow the exact free steps to put it online at a public URL, and learn the few pitfalls that break a deployment.

You don't need to already know

We teach all of this from scratch today, in plain steps:

  • how to save a trained model to a file and load it back,
  • what a "web app" is, and how a handful of Python lines becomes a web page,
  • how deploying to a free public URL actually works, click by click.

The little we assume: that you can run a notebook cell, and that you have met a trained model once before (any of the earlier machine-learning sessions is plenty). If either feels shaky:

You do not need any web, HTML, or server knowledge. Streamlit lets you build the whole page in plain Python, and the free hosting does the server part for you.

If you already code, skip ahead and look for the cells marked Stretch (optional) in the notebook.

By the end you can

  • Explain a trained model as a function f(x), and deployment as putting that function on the internet.
  • Save a fitted model with joblib.dump and load it back with joblib.load, no retraining.
  • Read a small Streamlit app and find its four blocks: load the model, collect inputs, predict, display.

For the mathematically curious (optional)

Everything above is enough to do the lab. This box is a bonus, and none of it is needed to finish.

Today's mathematical object is deliberately light: a trained model is a function, ŷ = f(x). It takes an input (here, four flower measurements; in your projects, a flat's size or a borrower's details) and returns a prediction. That is the same function idea from first-year calculus and the linear maps of the earlier machine-learning sessions. Deployment adds nothing to the mathematics. It takes that finished function and gives it a public address, so a call to f(x) can come from anyone's browser instead of only from your notebook. The trade name for this move is exposing a function as a service. The whole session is engineering around an f you already built.

New words in this session

  • deploy — put your app on the internet at a public link so other people can use it.
  • Streamlit — a library that turns a plain Python script into a web page, with no HTML.
  • widget — an on-screen control (a slider, a box, a dropdown) that collects one input.
  • serialize (joblib.dump) — write a trained model to a file so it loads later without retraining.
  • requirements.txt — the list of exact package versions the hosting machine must install.
  • classifier — a model that sorts each case into one of a few named groups (here, the species).
  • caching (st.cache_resource) — load the model once and reuse it, instead of on every click.

CODE # Block 1: load the saved model, only once @st.cache_resource def load_model(): return joblib.load("iris_model.joblib") model = load_model() # Block 2: the page heading st.title("Iris flower classifier") # Block 3: collect the inputs (one line per slider) petal_length = st.sidebar.slider("Petal length (cm)", 1.0, 7.0, 1.4) # Block 4: predict, and show the answer predicted_number = model.predict(input_row)[0] st.metric(label="Predicted species", value=predicted_name)

One thing to know: the file runs again on every change

  • When the user moves a slider, Streamlit runs app.py again, from the first line to the last.
  • That is why the page always shows the new answer.
  • Loading the model again on every move would be slow.
  • @st.cache_resource tells Streamlit: load the model once, then keep it in memory.

Safety rules for a public app

  • Never
  • Passwords or API keys inside app.py
  • Real customer or personal data in a public repo
  • Very large data files in the repo
  • Calling it a 'production system' in an interview
  • Instead
  • Use Secrets in the Streamlit Cloud app settings
  • Use public or made-up data only
  • Upload only the small saved model
  • Call it a demo app; be proud of it as a demo
