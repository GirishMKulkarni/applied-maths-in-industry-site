The problem

A fund desk at a Mumbai asset manager has ₹100 crore to spread across a basket of Nifty stocks. They want the split that keeps the risk as low as possible for the return they are targeting. A computer searches through the possible splits and hands back an answer: "put this much in each stock". But the desk has to defend that number to a client and to a regulator. So there is one uncomfortable question behind every such answer. Is this genuinely the best split, or is it just where the search happened to stop?

That same question sits behind almost every "find the best setting" task in industry: the cheapest delivery routing, the line that best fits past sales, the boundary a bank draws between safe and risky loans. Today you meet the single property that decides whether you can answer that question with confidence.

The one idea

Picture the problem as a landscape and the answer as the lowest point. If the landscape is a smooth bowl, there is exactly one bottom. Drop a marble anywhere and it rolls to that same lowest point every time. So when the computer stops, you know for certain it found the best answer. Nothing better is hiding elsewhere.

If instead the landscape is wobbly, full of little dips, the marble settles in whichever dip it happens to be near. That might be far from the true bottom, and worse, you cannot tell from inside the dip. A bowl-shaped problem is called convex, and it is the kind a computer can always solve to the genuine best.

Here is the warm surprise waiting in this session. A whole family of models you have already built are secretly bowls: fitting a line, Ridge and Lasso, the support vector machine, the Nifty portfolio. Once a problem is a bowl, you only have to describe your goal and the rules you must obey, and a solver returns the guaranteed best answer. You describe the problem; the solver solves it. (A tool called CVXPY lets the confident write these problems out in maths notation, but you never have to in order to get the answer.)

For the mathematically curious (optional)

Everything above is enough to do the lab. This box is the extra depth for those who want it, and none of it is needed to finish.

Today's mathematical objects are the convex set and the convex function. A set is convex if, for any two points x and y inside it, the whole segment t·x + (1−t)·y for t in [0, 1] stays inside. A function is convex if every chord lies on or above its graph, equivalently f(t·x + (1−t)·y) ≤ t·f(x) + (1−t)·f(y). Their payoff is one sentence: in a convex problem, any local optimum is the global optimum, which is exactly why such problems are considered "solved".

The problems in the lab are all convex for a reason you can name. Least squares minimises the squared norm ‖Xw − y‖², a bowl. Ridge adds λ‖w‖₂² and Lasso adds λ‖w‖₁, both convex, so the sum stays a bowl. The SVM minimises ½‖w‖² subject to one linear constraint per point, a convex quadratic program. The Markowitz portfolio minimises wᵀΣw, convex because the covariance matrix Σ is positive semidefinite.

The KKT conditions are the calculus of the optimum, and we treat them as intuition only, never as a theorem to prove. At the best point the objective's downhill direction is exactly balanced by the active constraints, ∇f = −Σ λᵢ ∇gᵢ; each price λᵢ ≥ 0; and a constraint either binds or its price is zero (complementary slackness). For a convex problem, a point meeting these conditions is certified globally optimal. CVXPY automates all of this through Disciplined Convex Programming (DCP): you assemble the objective from known convex building blocks, CVXPY checks it really is convex, then a solver returns the global answer along with those prices. All of this is a bonus, not a gate.

New words in this session

  • convex set — a shape with no dents: the line between any two inside points stays inside.
  • convex function — a bowl-shaped cost: every chord lies on or above the curve.
  • convex optimization — finding the lowest point of a bowl-shaped problem, which a computer can always do reliably.
  • global optimum — the genuinely best answer, not just the best nearby.
  • local optimum — a dip that beats its neighbours but is not the overall best; a trap that only wobbly problems have.
  • CVXPY — a Python library where you write a convex problem as algebra and it returns the best answer.
  • quadratic program (QP) — a bowl-shaped objective with straight-line fences; the SVM is one.
  • support vector — a data point sitting right on the edge of an SVM's margin; a handful of these fix the whole boundary.

Full definitions are in the glossary.

1 · What 'convex' means — and why it's the easy case

  • Two pictures, then the payoff

A shape with no dents: a convex set

  • First picture: the SHAPE of the allowed answers.
  • A convex set is a shape with no dents.
  • Left: a disc. Any two points, the line between them stays inside.
  • Right: a crescent. Pick two points and the line pokes outside — so it has a dent.

Pick any two points in the shape; the whole segment joining them stays inside too.

A convex function is a bowl

  • Second picture: the COST over the allowed answers.
  • A convex function curves like a bowl.
  • Join two points on it with a straight line (a 'chord').
  • For a bowl, the chord always sits on or above the curve — no hidden humps.

Join two points on the curve; the straight chord never dips below it.

Quick check: is my problem a bowl?

  • Signs it IS a bowl
  • Warning signs (probably NOT)
  • Is the allowed region dent-free?
  • — straight-line limits are fine
  • — overlaps of dent-free shapes are fine
  • Is the cost a bowl over that region?
  • — built only from bowls we know
  • Yes to both means: solve it to the genuine best.
  • A cost with several dips
  • Multiplying two unknowns together (x times y)
  • 'Pick exactly 3 of these' rules
  • Whole-number-only decisions (S21)
  • Many 'if this, then that' rules
  • Anything that puts a dent in the shape

Bowl vs wobbly: the picture that matters most

Left: one bottom, always reachable. Right: many traps, and no way to know you found the best.

Bowl vs wobbly: local best = global best

  • Bowl-shaped problem
  • The best nearby is the best anywhere
  • The solver returns a guarantee it's optimal
  • Scales to thousands of unknowns
  • Same answer every run — no luck involved
  • Wobbly problem
  • Can get stuck in a poor dip
  • No guarantee you found the best
  • The answer depends on where you started
  • Needs restarts, tricks, and some luck

CODE OUTPUT ▸ import cvxpy as cp # X has a row [size, 1] per flat; y is the price weights = cp.Variable(2) # [slope, intercept] cost = cp.sum_squares(X @ weights - y) # the total squared miss cp.Problem(cp.Minimize(cost)).solve() # the S7 normal equation gives the very same line numpy_w = np.linalg.solve(X.T @ X, X.T @ y) print('CVXPY [w, b]:', weights.value.round(3)) print('NumPy [w, b]:', numpy_w.round(3)) CVXPY [w, b]: [1.923 7.168] NumPy [w, b]: [1.923 7.168]

3 · The SVM — the widest street

  • A worked example you can picture

The support vector machine, in words

  • Goal: draw a line that separates two groups — but not just any line.
  • Choose the line with the widest empty street on either side of it.
  • A wide street is safer on new data: there's room to be a little bit wrong.
  • The few points that touch the street's kerb are the 'support vectors' — they alone fix the line.

SVM: the widest street that separates the two groups

Make the street as wide as possible; only the circled support vectors decide where it goes.

Why the SVM is a bowl with straight fences

  • Widest street = making the length ½‖w‖² as small as possible — a bowl.
  • Each training point adds one straight-line limit: 'stay on your correct side of the street'.
  • A bowl cost plus straight-line fences is a 'quadratic program' (QP) — still a bowl.
  • So the SVM has one best answer and a fast, reliable solver.
  • Messy, overlapping groups add gentle 'slack' terms — still a bowl.

Fit the widest street with one call to SVC

  • One fit separates every applicant correctly, and just two edge applicants — the support vectors — pin the whole street.

CODE from sklearn.svm import SVC # applicants: 40 rows of [income, existing_emis]; labels +1 / -1 loan_svm = SVC(kernel='linear', C=1000.0) loan_svm.fit(applicants, labels) print('accuracy:', loan_svm.score(applicants, labels)) print('support vectors:', loan_svm.support_vectors_.shape[0]) for p in loan_svm.support_vectors_: print(f' income {p[0]:.1f} emis {p[1]:.1f}') OUTPUT ▸ accuracy: 1.0 support vectors: 2 income 51.1 emis 24.9 income 63.8 emis 12.7

4 · CVXPY — write the maths, get the answer

  • One tool for the whole family — this is the centrepiece

CVXPY: write the problem the way you'd write it on paper

  • Name your unknowns, then type the goal and the limits as algebra — almost exactly as the maths reads.
  • No need to hand-build a solver or reshape the problem into some solver's input format.
  • CVXPY first checks the problem is a bowl, then picks and calls a suitable solver for you.
  • It returns the genuine best answer, with a certificate that it IS the best.
  • Next slide: the five-line skeleton every bowl problem shares.

The CVXPY recipe — worth memorising

  • Every problem in today's family is these five steps with different algebra filled in. If you remember one slide, remember this one.

CODE OUTPUT ▸ import cvxpy as cp x = cp.Variable() # 1. name the unknowns objective = cp.Minimize((x - 3)**2) # 2. the goal (a bowl) constraints = [x >= 0] # 3. the rules (straight fences) prob = cp.Problem(objective, constraints) prob.solve() # 4. solve print(prob.status, x.value) # 5. 'optimal' = provably the best optimal 3.0

State a goal and rules; get the best plan

  • You name the unknowns, type the goal and the limits as algebra, and CVXPY returns the provably best weekly bake.

CODE OUTPUT ▸ cakes = cp.Variable() biscuits = cp.Variable() profit = 400*cakes + 500*biscuits # maximise weekly profit rules = [3*cakes + 2*biscuits <= 80, # flour: 80 kg 1*cakes + 3*biscuits <= 50, # oven: 50 hours cakes >= 0, biscuits >= 0] prob = cp.Problem(cp.Maximize(profit), rules) prob.solve() print('status:', prob.status) print('cakes:', round(float(cakes.value)), ' biscuits:', round(float(biscuits.value))) print('profit: Rs', round(float(profit.value))) status: optimal cakes: 20 biscuits: 10 profit: Rs 13000

Write the maths, get the answer

CVXPY checks your problem really is a bowl before it solves — so it never quietly hands back a wrong-ish answer.

Which tool for which problem?

Rebuild the SVM as a CVXPY program

  • Writing the SVM as 'shrink ½‖w‖² subject to one fence per point' reproduces scikit-learn's line exactly.

CODE # unknowns: the line's direction w and its offset b w = cp.Variable(2) b = cp.Variable() objective = cp.Minimize(0.5 * cp.sum_squares(w)) # widen the street # one straight fence per applicant: stay on your side by >= 1 fences = [labels[i] * (w @ applicants[i] + b) >= 1 for i in range(applicants.shape[0])] cp.Problem(objective, fences).solve() print('our w:', w.value.round(4), ' sklearn w:', loan_svm.coef_[0].round(4)) print('our b:', round(float(b.value), 4), ' sklearn b:', round(float(loan_svm.intercept_[0]), 4)) OUTPUT ▸ our w: [ 0.0818 -0.0784] sklearn w: [ 0.0818 -0.0784] our b: -3.2232 sklearn b: -3.2232

5 · Pitfalls & wrap-up

Common traps

  • Avoid
  • Running a solver on a wobbly problem and calling the result 'the best'
  • Writing expressions CVXPY can't confirm are bowls
  • Forgetting to put features on a similar scale first
  • Ignoring a rewrite that would make the problem a bowl
  • Do instead
  • First ask: is this problem actually a bowl?
  • Use the ready-made blocks (sum_squares, quad_form, norm)
  • Scale the features, then solve
  • Look for the bowl-shaped way to write it

Key takeaways

  • The real dividing line is bowl vs wobbly (convex vs non-convex), not simple vs complicated.
  • In a bowl the best point nearby is the best point anywhere — a solver's answer comes with a certificate.
  • Line-fitting, Ridge, Lasso, logistic regression, the SVM and portfolios are all bowls.
  • The five-line CVXPY recipe: unknowns, objective, constraints, solve, check 'optimal'.
  • Pick the tool by the problem's shape: PuLP for LPs and integer decisions, CVXPY for bowls, PyTorch for the wobbly world.
