The problem

India Post handles crores of letters. On every envelope is a six-digit PIN code, written by hand, and the sorting machines have to read those digits to send the letter the right way. Banks have the same headache with the amount written on a cheque. A human can glance at a scribbled "7" and know it at once. How do you get a computer to do the same, when no two people write a "7" the same way?

You cannot write down a rule for it. There are too many styles of handwriting to list. So instead you show the computer thousands of examples of each digit and let it work out the pattern for itself. That is a neural network, and by the end of today you will have trained one that reads handwritten digits.

The one idea

A neural network is a flexible function with a lot of little dials on it. Feed a picture in one end, a guess comes out the other. At the start the dials are set randomly, so the guesses are nonsense. Then you show it an example, check how wrong it was, and nudge every dial a tiny bit in the direction that would have made it less wrong. Do that across thousands of examples, again and again, and the dials settle into a setting that reads digits well.

That is the whole thing. A flexible function that learns from examples by nudging its dials to shrink its mistakes. The dials are called weights, the "how wrong" number is called the loss, and the nudging is the same downhill walk you may have seen in Session 7, just with far more dials at once.

What you'll build today

  1. Build the pieces of a network by hand in NumPy: one neuron, the "bend" (activation) that lets a network fit curves, and a full pass from input to prediction. You will see exactly what the dials do.
  2. Train a real neural network in PyTorch that reads the 8x8 handwritten digits, watch its mistakes shrink epoch by epoch, and measure how often it is right on digits it never saw. This is your portfolio piece: "I trained a neural network end to end."
  3. Meet a network that keeps the picture as a grid instead of flattening it (a convolutional network), and see the little pattern-detectors it slides over an image.

For the mathematically curious (optional)

Everything above is enough to do the lab. This box is the extra depth, and none of it is needed to finish.

Today's mathematical object is a composition of linear maps with nonlinearities. One layer computes h = f(Wx + b): a linear map Wx + b followed by a nonlinear "bend" f (such as ReLU). Stack a few of these and the whole network is f₃(W₃ f₂(W₂ f₁(W₁x + b₁) + b₂) + b₃). The nonlinearity matters because a composition of purely linear maps is again a single linear map, so without the bend, depth would buy you nothing.

Training minimises a loss L over all the weights by gradient descent: step each weight against its gradient ∂L/∂w. Those gradients are found by backpropagation, which is nothing more than the chain rule applied along the computation graph: ∂L/∂w = ∂L/∂ŷ · ∂ŷ/∂h · ∂h/∂z · ∂z/∂w, the product of the local derivatives along the path. Modern frameworks (here, PyTorch's autograd) compute this for you automatically, so you never hand-derive a gradient again. The first notebook does one such chain-rule calculation by hand and checks it numerically, so the word "backprop" stops being mysterious.

New words in this session

  • neuron — one small step that multiplies inputs by weights, adds them up, and bends the result.
  • weight / bias — the dials of the network: the numbers it adjusts while learning.
  • activation — the "bend" (like ReLU) that lets a network fit curves, not just straight lines.
  • forward pass — sending an input through the network to get a prediction.
  • loss — one number saying how wrong the current predictions are; smaller is better.
  • backpropagation — working out how to nudge each weight; it is the chain rule, run automatically.
  • epoch — one full pass over the training data during training.
  • tensor — PyTorch's array of numbers, like a NumPy array that can also track gradients.

What is a neural network?

The one idea

  • A flexible function with many tunable dials (weights).
  • Feed inputs in one end; a guess comes out the other.
  • At the start the dials are random — guesses are nonsense.
  • Learning = nudge the dials until the guesses are good.

The whole idea, in one picture

  • A picture goes in; a guess comes out.
  • Inside: lots of little dials (weights).
  • Wrong guess? Nudge every dial a little.
  • Repeat thousands of times.

A picture goes in, a guess comes out; nudge the dials until it's right.

One neuron: multiply, add, bend

A single neuron, drawn out

Multiply each input by its dial, add them up, add a bias, then bend.

One neuron, written out

  • Multiply each input by its dial, add them up, add a bias — then bend.
  • xᵢ — one input (e.g. one pixel of the picture)
  • wᵢ — that input's dial (weight); training chooses it
  • b — the bias, a fixed baseline added to the sum
  • z — the weighted sum; a — the output after the bend

The 'bend' — why a network needs it

Without a bend, layers collapse

Stacking 'multiply and add' with no bend is still one straight line.

Three common bends

  • ReLU: keep positives, zero the rest — the default.
  • Sigmoid: squash to between 0 and 1.
  • Tanh: squash to between −1 and 1.
  • Last bend fits the task: softmax for the ten digits.

ReLU is the modern default; sigmoid and tanh squash to a bounded range.

The default bend: ReLU

  • Keep a positive value as it is; flatten anything negative to zero.
  • z — the weighted sum coming in
  • a — what comes out after the bend
  • one plain kink is all the nonlinearity a layer needs

Stacking neurons into layers

A small network

  • Input → hidden layers → output.
  • Every arrow is a dial to be learned.
  • More hidden layers = 'deeper'.
  • Real networks have millions of dials.

Input → a couple of hidden layers → output. Every arrow is a dial.

Making a guess, learning from a wrong one

Making a guess (the forward pass)

Push the picture through the layers, left to right; a guess comes out.

How wrong was it? The loss (cross-entropy)

  • Reward the network for putting high probability on the correct digit.
  • yᵢ — 1 for the true digit, 0 for the rest
  • pᵢ — the probability the network gave digit i
  • only the true digit's term survives; smaller loss is better

Learning: send the blame back (backprop)

After a wrong guess, work out which way to nudge every dial.

Training: the downhill walk

The same downhill walk as S7

Find which way is downhill, take a step, repeat — just millions of dials.

The mistakes shrink, step by step

Each step nudges the dials; the mistake count trends down over training.

Don't let it just memorise

Judge on unseen digits, and stop early

  • A big network can simply memorise the data.
  • Judge only on digits it never saw.
  • Early stopping: quit when unseen error turns up.
  • Dropout: switch off some neurons while training.

Mistakes on studied digits keep falling; stop when unseen mistakes climb.

The digit-reader you'll build

The digits, and how the network sees them

  • Flatten each 8×8 image into 64 numbers.
  • Hidden layers with ReLU learn combinations of pixels.
  • Output: 10 scores → softmax → a probability each.
  • The guess is the digit with the highest probability.

Key takeaways

  • A neural network is a flexible function that learns from examples.
  • One neuron: multiply by dials, add them, add a bias, then bend.
  • The 'bend' (activation) is what makes stacking layers worth it.
