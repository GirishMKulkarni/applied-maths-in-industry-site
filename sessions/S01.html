The problem

Picture a small online store. Every evening a file lands with the day's orders, hundreds of rows: the amount, the city, whether the customer paid online. The owner wants three numbers before closing up. Total sales for the day. How many orders were above ₹1000, so free delivery kicked in. Which city bought the most.

You could do it by hand in a spreadsheet every single night, slowly, and get it slightly wrong when you are tired. Or you can write the steps down once, as code, and let the computer redo them in a second, exactly the same way, every evening forever. That is what today is about: writing those steps down.

The one idea

A program is a list of instructions you hand to a very fast, very literal assistant. It does exactly what you say, in order, without getting bored and without making an arithmetic slip. The catch is that it does exactly what you say, so you have to say it clearly.

The good news is that almost every program ever written is built from just a handful of instruction-types. Name a value. Notice what kind of value it is. Choose between two paths. Repeat some work. Bundle a few steps into a reusable recipe. Learn those five moves and you can read and write real code. Today you learn all five, and then you use them on four small classic programs.

What you'll build today

  1. Take your first steps: name values, meet the basic kinds of value, make a decision with if/else, repeat work with a for loop, and write your own reusable recipe (a function). You also meet lists and lookup tables.
  2. Turn a day's shop orders into the numbers the owner wants: total sales, how many earned free delivery, the biggest order, and a GST function.
  3. Build a small sales report from a lookup table of city sales: the grand total, the top city, and a function that labels customers gold / silver / bronze.
  4. Meet the while loop by answering a money question — how many years until a savings pot doubles — and a stock-reorder countdown.

For the mathematically curious (optional)

Everything above is enough to do the lab. This box is a bonus for readers who enjoy the connection to mathematics, and none of it is needed to finish.

Today's mathematical object is functions, sequences and sets, and Python turns out to be a clean notation for all three. A function in code (a named recipe: an input goes in, one output comes back) is exactly a function in the mathematical sense, a mapping x ↦ f(x): the same input always gives the same output. A Python list is a finite sequence a₀, a₁, a₂, …, with the one quirk that Python counts positions from 0. A Python set is a set in the set-theory sense: no duplicates, no order, and it supports union and intersection directly. Even set-builder notation has a twin: { x² : x ∈ S, x even } is written in Python as [x**2 for x in S if x % 2 == 0]. You will meet that twin in a Stretch cell. Seen this way, learning to code is mostly learning a second notation for ideas that already make sense.

New words in this session

  • variable — a name that holds a value so you can use it again later.
  • type — what kind of value something is: a whole number, a decimal, text, or true/false.
  • for loop — repeat a block of work once for each item in a collection.
  • while loop — repeat a block of work until a condition stops being true.
  • function (in code) — a named, reusable recipe: inputs go in, one answer comes back.
  • list — an ordered collection of values, written in square brackets.
  • dictionary (dict) — a lookup table that maps a key to a value.
  • prime number — a whole number above 1 whose only exact divisors are 1 and itself.

Full definitions are in the glossary.

1 · Why Python

Why Python is the language of industry

  • It is the common tongue of data work, machine learning and analytics. Nearly every team you might join speaks it.
  • It reads almost like plain English, so your energy goes into the idea, not into fighting punctuation.
  • Huge free toolboxes come ready-made: NumPy, pandas, scikit-learn. You stand on decades of other people's work.
  • It is free and runs everywhere — your laptop, a server, even a free browser tab. No licence, no cost.

One language for the whole job

Read data, compute, model, share — all without switching languages.

Programming is not a special talent you either have or lack. It is just writing your steps down clearly enough that a machine can follow them.

3 · The five building blocks

Five moves, and you can read real code

  • Name a value — give something a name so you can use it again.
  • Notice its kind — a whole number, a decimal, some text, true/false.
  • Choose a path — do one thing if a test passes, another if not.
  • Repeat work — do the same thing for every item, or until you're done.
  • Bundle steps into a recipe — a function you can reuse anywhere.

Move 1: naming a value

A variable is a name stuck onto a value, so you can refer to it later.

Naming a value, in plain steps

  • Writing total = 0 tells Python: from now on, the name 'total' means 0.
  • You can update it: total = total + 250 makes 'total' mean 250. Read it as 'work out the right side, then let the name point there'.
  • Good names save you: total, price, city — not a, b, c. Code is read far more often than it is written.
  • This is exactly how you'd keep a running tally by hand — just written down for the machine.

Name a value, then build a running total

  • Read total = total + shipping as 'work out the right side, then let the name point there'.

CODE price_per_item = 249 quantity = 3 shipping = 40 total = price_per_item * quantity # 249 * 3 total = total + shipping # add delivery on top print("items cost:", price_per_item * quantity) print("total bill:", total) OUTPUT ▸ items cost: 747 total bill: 787

Move 2: what kind of value is it?

  • A whole number (int): 0, 7, −42 — counts and quantities.
  • A decimal number (float): 3.14, 249.50 — prices, measurements.
  • Text (str): 'Pune', 'order paid' — always inside quotes.
  • True or False (bool): the answer to a yes/no question, like 'was it paid online?'.

Ask Python what kind each value is

  • type(...) reports each value's kind — the four you'll meet all week.

CODE number_of_orders = 42 # int (a whole number) average_bill = 517.50 # float (has a decimal point) top_city = "Pune" # str (text, in quotes) paid_online = True # bool (True or False) print(type(number_of_orders)) print(type(average_bill)) print(type(top_city)) print(type(paid_online)) OUTPUT ▸ <class 'int'> <class 'float'> <class 'str'> <class 'bool'>

4 · Choosing and repeating

This is where a list becomes a program

  • By default, Python runs your lines top to bottom, once each.
  • Choosing (if/else) lets the program take one path or another.
  • Repeating (for, while) lets it do the same work many times without you copying it out.
  • With just these, plus naming and recipes, you can express any of today's four classic programs.

if / else: choosing a path

Test a yes/no question; follow the Yes branch or the No branch.

Decide free delivery with if / else

  • The test order_amount > 1000 is True, so only the indented 'Yes' branch runs.

CODE order_amount = 1250 if order_amount > 1000: # runs only when the amount is above 1000 print("Order of", order_amount, ": free delivery") else: print("Order of", order_amount, ": delivery charged") OUTPUT ▸ Order of 1250 : free delivery

for and while: repeating work

for repeats once per item; while repeats as long as a test still holds.

Add up a day's orders with a for loop

  • The loop visits each order once, adding it to a running total — no copy-paste.

CODE # one evening's orders, in rupees order_amounts = [249, 1250, 517, 980, 1499, 340] total_sales = 0 for one_order in order_amounts: total_sales = total_sales + one_order print("number of orders:", len(order_amounts)) print("total sales :", total_sales) OUTPUT ▸ number of orders: 6 total sales : 4835

Two loops, two situations

  • for — once per item
  • while — until done
  • for loop
  • You know the collection to walk through
  • 'for each order in today's file'
  • Cannot run forever
  • The one you'll use most
  • while loop
  • You repeat until a test stops holding
  • 'while the guess is still too far off'
  • You must make the test eventually fail
  • Used when zooming in on an answer

Repeat with while until savings double

  • We don't know the number of years up front, so we loop until the test finally fails.

CODE balance = 10000 yearly_growth = 0.08 target = 20000 years = 0 while balance < target: balance = balance * (1 + yearly_growth) years = years + 1 print("years to reach Rs", target, ":", years) print("balance then : Rs", round(balance)) OUTPUT ▸ years to reach Rs 20000 : 10 balance then : Rs 21589

5 · Recipes, lists and lookup tables

A function is a reusable recipe

Inputs go in, the recipe does the work, and return hands one answer back.

Why we bother writing functions

  • Write a calculation once, then reuse it everywhere — no copy-paste.
  • Give a messy set of steps one clean name, so the big picture stays readable.
  • Test it once on an answer you know; trust it after that.
  • Big programs are just small, well-named recipes stacked together.

Write a GST recipe once, reuse it

  • def names the recipe; return hands the answer back so each call gives a fresh result.

CODE # define the recipe once def price_with_gst(amount): tax = amount * 0.18 return amount + tax # now just call it by name, as often as you like print("249 with GST :", price_with_gst(249)) print("1250 with GST:", price_with_gst(1250)) print("999 with GST :", price_with_gst(999)) OUTPUT ▸ 249 with GST : 293.82 1250 with GST: 1475.0 999 with GST : 1178.82

A list is a row of values

Each value sits at a numbered position — and Python counts from 0.

Four handy ways to hold a collection

  • Ordered rows
  • Bags & lookup tables
  • list
  • a row of items you can change: [250, 1200, 640]
  • tuple
  • a fixed row that won't change: (lat, lon)
  • set
  • a bag with no duplicates: {'Pune', 'Mumbai'}
  • dict
  • a lookup table, key → value: {'Pune': 4200}

A list of cities, a dict that looks them up

  • A list is fetched by position (from 0); a dict is fetched by its key.

CODE # a list: the cities that ordered today, in order cities_today = ["Pune", "Mumbai", "Pune", "Nagpur", "Pune", "Mumbai"] print("first city today:", cities_today[0]) # counting starts at 0 print("how many orders :", len(cities_today)) # a dict: a small lookup table, city -> count orders_per_city = {"Pune": 3, "Mumbai": 2, "Nagpur": 1} print("orders from Pune:", orders_per_city["Pune"]) OUTPUT ▸ first city today: Pune how many orders : 6 orders from Pune: 3

Common first-timer traps

  • Watch out for
  • Thinking the first item is at position 1
  • Reading x = x + 1 as an equation to solve
  • Mixing up = (name it) and == (compare)
  • Expecting 5 / 2 to give 2 (it gives 2.5)
  • Writing 250 vs '250' — number vs text
  • Do instead
  • Remember Python counts from 0
  • Read = as 'let this name refer to'
  • Use == only to ask 'are these equal?'
  • Use // when you truly want a whole-number answer
  • Keep quotes for text; drop them for numbers
