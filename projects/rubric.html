How the project is marked

One hundred marks, the same for all six briefs. Each block matches a stage of the method.

Worth What earns it
The decision and its cost 10 A cost in rupees for each direction of error, committed to git before any modelling. If it is vague or written late, this block gets zero.
Data work and the split 15 Eight or more questions answered about the data before any modelling, with the one surprise written up. The split done the way the brief requires, locked before feature engineering, with a written note on what the easy split would have leaked.
Features and the leakage hunt 15 Every learned transformation inside a pipeline. A written account of the leaking columns you found and what you did about them. Fitting a transformer before the split scores zero for this block.
The unsupervised pass 15 Dimension reduction with variance reported. Cluster count chosen from four pieces of evidence, with the disagreement between them discussed. More than one clustering method. Groups given names a manager would use. The group label tested as a feature, with the result reported either way.
The model search 20 Every family from the method covered or excused. Three-stage search. A leaderboard with scores, fold spread and training time. A stated fit budget with the reasoning for it. Nested cross-validation on the winner, with the gap to the tuned score explained.
The metric and the threshold 15 The full panel computed. One metric defended from your own stage 1 costs, with an account of what the others would have chosen instead. Threshold from expected cost, not 0.5. Calibration checked if you report probabilities.
Error analysis and the memo 10 The worst cases studied and described in sentences. A group-behaviour check. Three pages a manager could act on with no notebook open.

Marks you lose

These are deductions from the total, not from a block.

Minus 25, a leaked test set. Any evidence that test rows influenced a choice: a scaler fitted before the split, a feature built from the full table, "we tried a few splits and this one worked". In industry, this one mistake makes an otherwise good project useless. So we treat it the same way here.

Minus 15, a metric chosen after the results. If the git history shows that your cost table came after your leaderboard, then your argument in stage 7 was made after seeing the results. It does not count.

Minus 15, a notebook that does not run. We clone your repo onto a clean machine and run everything top to bottom. It must download its own data and finish without a manual step. Fix the seeds so we get your numbers.

Minus 10, an undeclared borrowed notebook. Reading what others have published on these datasets is allowed and sensible. Presenting it as your own is not. Cite what you read.

What we are not marking

Not the score. Suppose one team gets a worse number and knows exactly why. Another team gets a better number and cannot explain it. The first team always gets more marks. Three of these datasets have a best possible score that is much lower than beginners expect. Finding that limit honestly is a result.

Not the length. Three pages means three pages, not more.

Not how many models you fitted. Ten thousand fits with no reasoning about the budget get fewer marks than fifteen hundred fits with a paragraph explaining the choice.
